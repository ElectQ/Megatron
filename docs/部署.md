# 部署到 VPS

一台能跑 Docker 的 VPS + 域名 `megatron.qshunter.top`。全流程一条 `deploy.sh`。

```text
浏览器 ─https─▶ Caddy(宿主机 :443, 自动 TLS)
                 └─reverse_proxy─▶ 宿主机 :8010 ─(端口映射)─▶ 容器 :8000 (uvicorn)
                                                                    └─ /app/data (卷 megatron_data) = SQLite + 密钥
```

端口说明:容器内 uvicorn 固定 `8000`;宿主机发布端口是 **8010**(`PORT` 可改),
特意避开 8000,留给本机其它 Python 服务。Caddy 反代目标是宿主机 `:8010`。

## 一、DNS(先做)

`megatron.qshunter.top` 的 **A 记录** → VPS 公网 IP。放行防火墙 **80 / 443**。
(Caddy 靠 80/443 的 HTTP-01 质询签 Let's Encrypt 证书,DNS 没生效就签不下来。)

## 二、装 Docker

```bash
curl -fsSL https://get.docker.com | sh
```

## 三、拉代码

```bash
git clone git@github.com:ElectQ/Megatron.git
cd Megatron
# 合并到 master 后直接用 master;未合并前用功能分支:
git checkout feat/phase0-source-ingest
```

## 四、首次部署

```bash
bash deploy.sh
```

会自动:生成 `.env`(随机 session secret、**admin 密码**〔屏幕打印,存好〕、ingest token)、
构建镜像、`alembic upgrade head`、起容器。域名 `megatron.qshunter.top` 已预置进 `.env`。

## 五、填 LLM 密钥后重启

编辑 `.env`,填 `MEGATRON_DEEPSEEK_API_KEY`(要钉钉推送再填 `MEGATRON_DINGTALK_*`),然后:

```bash
bash deploy.sh          # 重新 down/up,加载新 env
```

## 六、HTTPS 入口(Caddy)

仓库自带 `Caddyfile`(已指向你的域名、反代 `localhost:8010`)。装好 Caddy 后:

```bash
caddy run --config ./Caddyfile        # 调试;正式用 systemd 托管
```

完成后:`https://megatron.qshunter.top` = 公开博客前台,`/ui/login` = 后台。
推送里的「查看今日详情」链接会自动用这个域名。

# 数据安全(备份 / 恢复)

**数据都在命名卷 `megatron_data`**(挂到容器 `/app/data`):SQLite 库 `megatron.db`
+ 首启生成的密钥。容器重建/升级(`deploy.sh update`)**不丢**;只有 `deploy.sh clean`
会连卷一起删。

## 备份

```bash
bash deploy.sh backup
# → backups/megatron-YYYYMMDD-HHMMSS.tar.gz
```

备份会**短暂暂停容器**几秒,确保 SQLite(WAL 模式)快照一致,然后自动恢复。

> ⚠️ 本地备份会随磁盘一起死。务必再拷一份到别处:
> `scp backups/*.tar.gz you@another-host:~/megatron-backups/`,或传对象存储。

定时备份(crontab,每天 04:00):

```cron
0 4 * * * cd /path/to/Megatron && bash deploy.sh backup >> backups/cron.log 2>&1
```

## 恢复

```bash
bash deploy.sh restore backups/megatron-YYYYMMDD-HHMMSS.tar.gz
```

会先确认再**覆盖**当前数据,暂停容器 → 还原卷 → 重启。

## 忘记 admin 密码

不用删数据重建。容器跑着时,直接重置(只改这一个用户的密码,其它数据不动):

```bash
bash deploy.sh reset-password              # 生成一个随机新密码并打印
bash deploy.sh reset-password 'YourNewPass' # 或指定新密码
```

等价于在容器里跑 `python -m megatron.main reset-password`。重置后用新密码登录,
再去「系统设置」改成你要的。用户不存在会顺带创建。

## 其它安全建议

- `.env` 含密钥,已被 `.gitignore` 忽略,**不要**提交或外传;换机迁移时随备份一起安全拷贝。
- 只用 HTTPS 对外(Caddy)。如无需 IP 直连,可把 `docker-compose.yml` 的端口映射收成
  `127.0.0.1:${PORT:-8010}:8000`,让公网只能经 Caddy 443 进来,`8010` 不暴露。
- 后台 admin 密码可在「系统设置」里改;首启随机密码请立即改成自己的。

# 日常运维

```bash
bash deploy.sh update    # git pull + 重建 + 重启(不丢数据)
bash deploy.sh backup    # 备份(含 /app/data/logs)
bash deploy.sh logs      # 实时日志(stdout);历史日志见文件
bash deploy.sh status    # 容器状态
bash deploy.sh reset     # ⚠️ 清掉本机旧数据(卷、密钥、孤儿容器)后全新部署
bash deploy.sh clean     # ⚠️ 只停容器 + 删所有数据,不重新部署
```

## 日志在哪

同时写两处,内容一样:

- **容器 stdout**:`bash deploy.sh logs`(= `docker compose logs -f --tail 100`),实时看。
- **文件**:`/app/data/logs/megatron.log`,在数据卷上,`deploy.sh update`/`down` 都不丢。
  10MB 轮转、保留 5 份(`megatron.log.1` … `.5`)。

```bash
bash deploy.sh logs                          # 实时
bash deploy.sh logs | grep -E 'llm\.|runner\.'   # 只看 LLM / 分析链路
docker compose exec web tail -f /app/data/logs/megatron.log
docker compose exec web grep 'llm.chat.failed' /app/data/logs/megatron.log
```

事件名就是日志里的第一段文本(如 `llm.chat.start` / `llm.chat.failed` /
`runner.done` / `scheduler.acquire.ready`)。

> 查「上一次跑出了什么」不要只看日志:重启过的 run 记录在 `analysis_runs` 表里
> (含 `result` / `error` / `prompt_snapshot` / token 数),后台 Run History 页面也能看。

# Dokploy · Phase A（SQLite 单实例）

此阶段不迁 PostgreSQL：Dokploy 接管镜像、域名、TLS、环境变量和持久卷；SQLite 仍是
单机数据库。**一个应用只能开一个副本**，并采用 stop-first / recreate 发布。

允许新旧实例短暂并行的唯一场景是**预发布验证**：新实例使用复制出来的新 volume，并设置
`MEGATRON_SCHEDULER_ENABLED=false`。它绝不能与旧实例共用 `/app/data`，也不能在切流后
让两边的 scheduler 同时跑：否则会重复拉取、分析、DeepSeek 调用和推送，两个 SQLite 文件
也会立刻分叉。

## Dokploy Compose Service

Dokploy UI 创建 **Compose Service**，Git 仓库指向本仓库，**Compose Path 必须精确填写**：

```text
./docker-compose.dokploy.yml
```

不要填写根目录的 `docker-compose.yml`：那是旧的本地/手工部署文件。两个 stack 都会启动
scheduler，不能同时运行。

服务名是 `app`。这个文件刻意没有 `ports`、`container_name`、`restart`：Dokploy 负责
反代、域名、TLS 和生命周期。内部端口填 `8000`，不要发布宿主机端口。

镜像入口为 `/app/scripts/start.sh`：先执行 Alembic，再以 PID 1 启动 uvicorn，SIGTERM 能
正常触发 scheduler 和数据库的 shutdown。

Health Check：

```text
Path: /ready
Port: 8000
Grace period: 60 seconds
```

`/health` 只表示进程活着；`/ready` 额外执行数据库 `SELECT 1`，迁移失败、卷挂错、数据库
不可用时返回 503，Dokploy 不会接流量。

## Persistent Storage

在 Dokploy 给应用添加一个本地 Docker volume：

```text
Mount path: /app/data
```

SQLite WAL 只支持单机本地磁盘；不要用 NFS/SMB 共享卷，也不要把同一个卷挂给多个副本。

首次迁移已有服务时，使用旧项目的完整备份，**不要只复制 `megatron.db`**：

```bash
cd /path/to/Megatron
bash deploy.sh backup
# 得到 backups/megatron-YYYYMMDD-HHMMSS.tar.gz，内容是完整 /app/data
```

## 分阶段迁移和最终切换

你可以保持旧站在线完成第一轮复制和内部验证；但**最终切换一定有一次很短的停写窗口**。
不能把旧站继续运行几天再停：它会持续写入旧 SQLite，Dokploy 上的是另一份副本，数据必然
分叉。

1. 用现有一致性快照填充 Dokploy volume，首次预发布启动时**必须**设置：

   ```env
   MEGATRON_SCHEDULER_ENABLED=false
   ```

   这是强制项，不是可选优化：旧站仍在运行时，若新实例启动 scheduler，会重复 cron、拉取、
   DeepSeek 调用和 webhook 推送。此时只验证 `/ready`、登录、历史 run、Provider Test 和日志；
   不要点手工 Run，也不接公网域名。

2. 准备切流时，先等待旧站没有 `queued/running` 的分析任务，再停止旧 `web` 容器。
   对旧 `/app/data` 做**最后一次**一致性备份，将它覆盖导入 Dokploy volume。数据库快照必须
   最终落为：

   ```text
   /app/data/megatron.db
   ```

   你给出的迁移包内文件名是 `megatron-consistent-snapshot.db`，导入时需要改名为
   `megatron.db`；不要直接解压后就启动。并先用 `tar tzf` 确认包内是否真的有
   `.session_secret` 和 `.ingest_token`。

3. Dokploy 使用最终数据启动（scheduler 仍为 `false`），确认 `/ready` 后再切 Cloudflare。
   新站接流量后，将 `MEGATRON_SCHEDULER_ENABLED` 改回 `true` 并 Redeploy。旧容器保持停止，
   旧 volume 和备份保留数天作为回滚点。

这样预验证阶段用户无感；真正的中断只发生在第 2 步最终快照到第 3 步 `/ready` 期间。SQLite
单实例下这是避免重复任务与数据分叉的必要代价。

## Dokploy Secrets / Environment

在 Dokploy 填这些值（不使用仓库 `.env`）：

```env
MEGATRON_ENV=production
MEGATRON_DATABASE_URL=sqlite+aiosqlite:////app/data/megatron.db
MEGATRON_MASTER_KEY=<旧库已有 enc:v1: 密钥时必须填原值；纯明文旧库可新增长期固定值>
MEGATRON_ADMIN_PASSWORD=<首次启动密码；已有 users 表时不会覆盖>
MEGATRON_BASE_URL=https://你的域名
MEGATRON_DEEPSEEK_API_KEY=<有效 key>
MEGATRON_LOG_DIR=/app/data/logs
MEGATRON_LOG_FORMAT=json
MEGATRON_RUN_MIGRATIONS=1
# 首次预发布必须 false；完成最终同步、Cloudflare 切流后才改 true 并 Redeploy。
MEGATRON_SCHEDULER_ENABLED=false
MEGATRON_FORWARDED_ALLOW_IPS=*
```

迁入**已有** `/app/data` 时，以下 Secret 要么不填（应用会从导入卷的隐藏文件读取），要么
必须填旧值；绝不能临时生成一套新值：

```env
MEGATRON_SESSION_SECRET=
MEGATRON_ADMIN_TOKEN=
MEGATRON_INGEST_TOKEN=
MEGATRON_DAY_TOKEN=
```

否则已有登录会话、采集端 Bearer token、以及历史消息中的日刊链接都会失效。

`MEGATRON_MASTER_KEY` 一旦用于加密数据库中的 Provider/Webhook 密钥就不能换；换掉后旧密钥
无法解密。生产 schema 只由启动脚本的 `alembic upgrade head` 管理，应用不会再执行
`create_all`。

## 日志与排障

日志同时存在：

- Dokploy Logs：容器 stdout，production 为一行一个 JSON，便于按 `event` / `run_id` 搜索；
- `/app/data/logs/megatron.log`：持久卷上的文件，10MB 轮转、保留 5 份。

LLM 排查搜索事件：`llm.chat.start`、`llm.chat.done`、`llm.chat.failed`、
`runner.bundle_unparsed_output`。`llm.chat.done` 含 `finish_reason`、`content_chars` 和 token
数；不再把 DeepSeek 的空响应伪装成“今日无必看条目”，会改发明确错误提示。

## 还未做的事

本阶段没有拆分 scheduler，也没有迁 PostgreSQL，因此不能扩副本。未来拆成 web + 单独的
scheduler 后，只有一个服务设 `MEGATRON_RUN_MIGRATIONS=1`；届时再切 PostgreSQL，才能安全
做多副本和滚动发布。

## 机器上有之前的部署 / 想全新重置

一条命令清旧数据 + 全新起(会二次确认;之前的库、密钥、孤儿容器都清掉,
`.env` 重新生成、admin 密码重出):

```bash
bash deploy.sh reset
```

若这台机器上还有**更早、非本 compose 项目**留下的卷/镜像(比如换过目录名),
`reset` 清不到,手动查一下再删:

```bash
docker volume ls   | grep megatron    # 看有没有多余的旧卷
docker volume rm <旧卷名>              # 确认无用后删除
docker image  ls   | grep megatron    # 旧镜像(可选清理)
```

> 想保留旧数据就先 `bash deploy.sh backup`,再 `reset`。
